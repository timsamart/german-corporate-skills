# In fünf Minuten anfangen

Wähle den Skill für das benötigte Ergebnis und installiere ihn über die Anleitung im [README](../README.md). Gib Unterlagen, Adressat, gewünschte Handlung und vorhandene Unternehmensvorlage mit. Nutze für Unternehmensunterlagen eine dafür zugelassene Umgebung.

## Welchen Skill brauche ich?

| Ich brauche … | Skill |
| --- | --- |
| konkrete Änderungen an einem vorhandenen Deck | `$praesentations-review` |
| eine überprüfbare Wirtschaftlichkeitsaussage | `$business-case-pruefung` |
| eine Vorlage, über die entschieden werden kann | `$entscheidungsvorlage` |
| Vorbereitung auf die Fragen in einer Sitzung | `$gremienvorbereitung` |
| eine belastbare Prognose und Unterstützung | `$projektstatus` |
| Beschlüsse und Aufgaben aus einer Sitzung | `$ergebnisprotokoll` |
| eine klare, verwendbare Nachricht | `$stakeholder-kommunikation` |

## Kopierbare Aufträge

Passe Umfang, Ziel und Anrede an deinen Fall an.

### Deck

```text
$praesentations-review
Prüfe dieses Deck als Vorabunterlage für die Geschäftsführung.
Wir wollen über den nächsten Pilotschritt entscheiden.
Nenne die drei entscheidenden Schwächen mit Foliennummer,
Auswirkung und konkreter Änderung. Schlage einen Abschluss vor.
Höchstens 400 Wörter. Nutze unsere vorhandene Vorlage.
```

### Business Case

```text
$business-case-pruefung
Prüfe diesen Case. Unser Ziel ist der Abbau von Rückständen.
Rechne die entscheidenden Positionen nach und zeige, welche
betriebliche Änderung den Nutzen realisieren soll. Nenne die
wichtigsten fehlenden Nachweise. Höchstens 350 Wörter.
```

### Entscheidung

```text
$entscheidungsvorlage
Schreibe aus diesen Unterlagen eine kompakte Entscheidungsvorlage.
Das Gremium darf nur den angegebenen Umfang freigeben.
Stelle zuerst den Beschlussvorschlag, dann Optionen, Zielkonflikt,
benötigte Mittel und offene Bedingungen dar. Höchstens eine Seite.
```

### Sitzung vorbereiten

```text
$gremienvorbereitung
Ich vertrete diese Empfehlung im Lenkungsausschuss.
Bereite einen kurzen Einstieg, die drei stärksten sachlichen
Einwände mit ehrlichen Antworten und meine Abschlussfrage vor.
Vier Minuten Redezeit; Raum für Fragen lassen.
```

### Projektstatus

```text
$projektstatus
Schreibe den Status für den Bereichsleiter aus diesen Updates.
Zeige Soll, aktuelle Prognose, Kapazitätskonflikte und die
konkrete Unterstützung, die gebraucht wird. Neue Maßnahmen
bleiben Vorschläge. Höchstens 250 Wörter.
```

### Protokoll

```text
$ergebnisprotokoll
Erstelle aus diesen Notizen ein Ergebnisprotokoll als Entwurf.
Erhalte Beschlüsse, Bedingungen, vereinbarte Aufgaben und deren
Nachverfolgung. Vorschläge und offene Zuständigkeiten getrennt
halten. Die Sitzung fand am [Datum] statt.
```

### Nachricht

```text
$stakeholder-kommunikation
Überarbeite diese Nachricht sachlich und klar in Sie-Form.
Bitte um die genannte Klärung. Zahlen, Bedingungen und bestehende
Zusagen erhalten. Höchstens 120 Wörter; keine neue Frist.
Liefere zuerst die verwendbare Mail.
```

## Eine sinnvolle Arbeitskette

**Case prüfen → korrigierte Grundlage verwenden → Entscheidungsvorlage → Sitzung vorbereiten → Ergebnisse nachhalten.** Gib beim Wechsel die verifizierte Grundlage und offenen Punkte weiter. Ein Skillaufruf ist keine Genehmigung, Budgetfreigabe oder Versandbeauftragung.

Eine gezielte Sprachkorrektur oder kleine Rechnung bleibt ein kleiner Auftrag. Du musst keine zusätzlichen Gremien, Messverfahren oder Workshops organisieren, um die Sammlung zu verwenden.

## Beispiele

Jeder Skill enthält das bisherige durchgerechnete Beispiel und eine neue [Arbeitsweise](research/methods-v0.3.0.md) mit einem fiktiven Arbeitsfall und einem Gegenfall. Sie zeigen, wie Annahmen und Vorschläge erkennbar bleiben. Verwende die Beispieldaten nicht als Eingaben für deine Unterlagen.
